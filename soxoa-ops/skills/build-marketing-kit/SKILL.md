# Build a marketing kit

Create coordinated campaign assets whose claims can be traced back to the same dated source of truth. Adapt the deliverables to the request; a full kit is useful only when the audience needs it.

## Establish current truth

Read the supplied positioning, audience, current offer, live capability evidence, approved visual assets, and intended campaign dates. Confirm which source controls when drafts conflict. If release-time price or product behavior cannot be verified, omit it or mark it for verification; do not promote historical information into a current claim.

Build a small claim register for material assertions: wording, source, observation window, definition/denominator for metrics, evidence type, allowed use, and review status. Distinguish customer results, internal experiments, public-source tests, synthetic tests, and illustrative examples. Do not invent testimonials, attribution, traction, or quotes.

## Build a coherent set

- Use the same audience, buyer problem, product mechanism, factual scope, and main call to action across the assets. Allow channel-specific phrasing without changing the promise.
- For a requested full kit, create a concise brand/claim guide, a one-page offer explanation, press facts and proposed angles, a dated content calendar, and editable copy. Include video storyboards or graphics only when requested and supported by the available tools.
- Mark proposed spokesperson quotes as drafts requiring that person's approval. Keep approved quotations exact and attributed. A generated sentence is not a quotation someone actually gave.
- Let calendar rows name a concrete subject, format, evidence asset, call to action, owner, and review status. Choose a workable cadence rather than filling every date with repetitive promotion.
- Preserve existing brand assets and design rules. State missing assets instead of manufacturing an official logo or unsupported visual proof.

## Verify the delivery

Check cross-asset claims, prices, dates, destinations, and approval labels. For formatted documents, export and inspect the rendered pages at readable size using available document tools. Fix clipping, dense tables, poor contrast, missing characters, and unexplained blank space. Record what was actually inspected; source text alone does not prove the export is sound.

Keep editable sources with the exports and a short delivery manifest naming versions, review date, unresolved approvals, and checks performed. Recheck changeable claims immediately before an authorized public release. If rendering or current-source access is unavailable, deliver the useful draft and identify the remaining checks accurately.

Do not publish, buy media, schedule posts, send materials, or approve quotations merely because a kit was requested. Follow the user's actual distribution instruction and existing restrictions.

## Illustrative request

“Use build-marketing-kit for this product launch. Create a one-pager, press facts, draft founder quotes, and a four-week calendar from the attached truth sheet and brand guide. Flag every claim that needs fresh evidence.”

This instruction package is a draft. Its historical production method does not establish that the new package has been tested in Claude.
